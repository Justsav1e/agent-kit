# Distinctive website execution

Use for an explicitly ambitious brand, portfolio or experiential website.
This is a creative execution route, not an extra gate for routine CSS fixes.
Award-level ambition is a target for craft, not a claim that a workflow can
guarantee an award or that more animation necessarily improves a site.

## Establish a point of view

Start with the audience, product and desired impression. State one specific
creative thesis and the signature behavior/composition that expresses it.
If directions are unresolved, compare a small set of genuinely different
directions by relevance, distinctiveness, feasibility and responsive potential.
Use existing creative skills selectively; stop divergence once direction is set.

Inspect a few useful references at the level of typography, pacing, composition,
material, imagery and interaction. Record which principle is transferable and
why; avoid copying a whole site or treating an award label as a design brief.
Do not replace a distinctive concept with the easiest familiar template.

## Prove the direction in one real slice

Before repeating the design across a large site, implement one representative
section and its transition to a neighboring section. Use real copy, intended
fonts and actual approved imagery where available. Declare missing assets;
placeholders do not prove the final composition. Follow the project's image policy.

The slice should expose the hardest important relationship: expressive type,
image crop, spatial alignment, signature motion, or scroll continuity.
Show desktop and an intentionally composed mobile version. For a web app,
include a real meaningful state or user action rather than a static landing.

The owner can assess the visible direction at this point if a material choice
remains. Existing approval is sufficient: do not request repeated approval for
routine execution. Record accepted visual properties in existing design docs.

## Carry a visual system through the page

Extract only demonstrated rules: type roles, spacing rhythm, content widths,
image treatment, composition anchors, motion vocabulary and interaction states.
Use shared CSS/components where those relationships repeat. Do not force every
section into one layout or invent a general framework for a unique scene.

Design page rhythm deliberately: variation in scale and density, transitions
between sections, moments of emphasis and quieter reading. Check the entire
journey as well as the hero. Do not equate a spectacular first screen with a
finished product.

## Motion and responsive execution

Describe what moves, why, its trigger, start/end states and interruption behavior.
Watch the transition, reverse scroll and resize where relevant. A screenshot
cannot prove timing, continuity or the absence of transform conflicts.
Mobile may recompose the idea; reduced motion must preserve meaning.
Use interaction-concept/responsive-geometry only when those concerns warrant it.

## Craft and acceptance

Use [frontend-polish](../../frontend-polish/SKILL.md) for bounded
polish. Separate defects from deliberate art direction. Check typography and
line breaks, image quality/crops, alignment, section rhythm, meaningful states,
interaction feedback and motion in the actual renderer.

Acceptance asks whether the thesis is visible, the page feels coherent, the
signature survives responsive changes, and the intended journey remains usable.
Performance and accessibility remain part of quality, not optional cleanup.
Capture known weak points honestly; do not claim premium quality from a build.

Benchmark with a real polish request on the proof slice: can the agent improve
one property while preserving accepted neighboring states and transitions?
Record regressions, user corrections, time and cost. This must be observed
before claiming the process improves output across models.
